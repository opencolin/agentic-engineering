# PM #4 — Distribution, Community, Growth

**Lens:** How readers find, return to, and contribute to the site.
**Author:** PM Council subagent (general-purpose), `agentId: af05122d18287d904`
**Status:** Read-only research; no files modified.

---

## 1. Discovery Surface (Current State: Bare)

`index.html` has only `<title>`, `<meta description>`, viewport, Google Fonts preconnect. No `og:*`, no `twitter:*`, no canonical, no JSON-LD, no favicon (`/img/` only has `nebius-logo.svg`), no `sitemap.xml`, no `robots.txt`, no 404. For a curated reference that lives or dies by being linkable on X/HN/LinkedIn, this is the single biggest growth gap.

Ship in this order:
- **OG + Twitter cards per page.** Because `build.sh` inlines everything into one `index.html` and routing is hash-based (`#page`), crawlers/unfurlers see one document. Fix: real HTML per page at build (`/approaches`, `/patterns`, …), each with its own `<title>`, `og:title`, `og:description`, `og:image`, `og:url`, `twitter:card=summary_large_image`. Hash routing can stay as a progressive enhancement.
- **Per-page OG images.** Auto-generate 1200×630 PNGs via `@vercel/og` keyed on page slug — title + section label on the dark theme. ~50 lines.
- **`sitemap.xml` + `robots.txt`** generated by build from the page list. Submit to Google Search Console.
- **JSON-LD `TechArticle`** per page with `author`, `dateModified` (from `git log -1 --format=%cI content/<page>.md`), `headline`.
- **Canonical URLs** point to the production domain.
- **Real 404** at `/404.html` surfacing search + ToC.

## 2. Subscribe / Retain — One Recommendation

**Buttondown + RSS, no push.** Buttondown wins (vs Beehiiv/Substack) because: free under 100 subs, plain-text feel matches the site, first-class RSS-to-email (changelog drives newsletter automatically), no platform lock-in. **One RSS feed** at `/feed.xml` driven by changelog + dated entries — not per-page. Embed Buttondown form on `index.md` + changelog. Skip web push: wrong audience.

## 3. Contribute — Flow for v2

Today, adding a page = edit `build.sh:86` + edit `index.html` sidebar + add markdown. Gatekeeping by accident. v2:
- **Drive sidebar + page list from a single `content/manifest.json`** (slug, title, group, order). Both `build.sh` and sidebar read it. New page = add markdown + one JSON line.
- **`.github/ISSUE_TEMPLATE/`** — three: `suggest-addition.yml` (org/person/tool + link + 1-paragraph why), `correction.yml` (page + section + fix), `new-page.yml` (proposal).
- **`PULL_REQUEST_TEMPLATE.md`** — checklist for "ran `bash build.sh`".
- **`CONTRIBUTING.md`** documenting the manifest flow.
- **"Suggest an edit" link** on every rendered page → `github.com/opencolin/agentic-engineering/edit/main/content/<slug>.md` — one line in `js/main.js`.

## 4. Community — One Recommendation

**No Discord. Use GitHub Discussions + a "Discuss this page" link per page.** Audience is engineers already on GitHub. A Discord adds moderation burden a solo maintainer will lose. Enable Discussions, create categories matching sidebar groups, render a per-page "Discuss" link that searches/creates a discussion tagged with the slug. Revisit Discord only after >500 weekly active readers.

## 5. Measurement — Three Metrics, One Tool

**Plausible Cloud** (~$9/mo, GDPR-clean, custom events). Instrument:
1. **Weekly unique readers per page** — which sections deserve depth vs pruning.
2. **Outbound click-through to vendor/person links** (Plausible auto-tracks `outbound: click`) — proves the site does its referral job.
3. **Newsletter conversion rate per page** (custom event `signup` with `page` prop) — best-converting page becomes the home hero.

Skip Vercel Analytics (thin) and PostHog (overkill — no session-replay needed for a static reference).

## 6. Three Releases to v2

- **R1 — Linkable (week 1):** per-page HTML output, OG/Twitter cards, `@vercel/og` images, sitemap/robots, JSON-LD, canonical, 404 page, Plausible. Discovery surface in one PR.
- **R2 — Subscribable (week 2):** `/feed.xml`, Buttondown form on index + changelog, RSS-to-email automation, "Discuss this page" + "Suggest an edit" links, GitHub Discussions enabled.
- **R3 — Contributable (week 3):** `content/manifest.json` refactor, `.github/` issue + PR templates, `CONTRIBUTING.md`, public roadmap as a GitHub Project board linked from sidebar.

Each release ships independently and creates a distinct loop: R1 = discovery, R2 = retention, R3 = supply-side growth.
