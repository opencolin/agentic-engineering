# v1.2 — Discovery Surface + Build Hygiene

**Worktree:** `../wt-v1.2-discovery-build`
**Branch:** `claude/v1.2-discovery-build`
**Estimated effort:** 1 week
**Depends on:** v1.1 merged (so TOC/mobile is in main before this release adds per-page HTML)

---

## Goal

Make the site linkable on social, indexable by Google, and safe to add pages without breaking the sidebar.

## Acceptance Criteria

### Build hygiene
- [ ] `content/manifest.json` exists; shape `{ "groups": [{ "label": "...", "pages": [{ "slug": "...", "title": "..." }] }] }`.
- [ ] `build.sh` reads the manifest for slug list (replaces hardcoded `for page in ...` loop) and for sidebar HTML (replaces heredoc).
- [ ] Adding a page = drop one `.md` into `content/` + add one line to manifest. No `build.sh` edit, no sidebar HTML edit.
- [ ] `scripts/check-links.sh` exists; called by `.github/workflows/ci.yml`; fails on broken `[text](other.md)` refs.
- [ ] `bash build.sh --check` mode exits non-zero if generated `index.html` differs from committed copy.
- [ ] `.github/workflows/ci.yml` runs both checks on every PR.

### Discovery surface
- [ ] Each page emitted as a real HTML file at `/<slug>/index.html` (in addition to the existing hash routing for back-compat).
- [ ] Each per-page HTML has page-specific `<title>`, `<meta name="description">` (sourced from existing `<!-- description: -->` comment), `<link rel="canonical">`, `og:title`, `og:description`, `og:image`, `og:url`, `twitter:card=summary_large_image`.
- [ ] Per-page OG images generated via `@vercel/og` edge function; URL pattern `/og/<slug>.png` returns a 1200×630 PNG with H1 + section label on dark theme.
- [ ] `/sitemap.xml` generated from manifest at build time.
- [ ] `/robots.txt` exists; allows all; points to sitemap.
- [ ] JSON-LD `TechArticle` block on each page (`headline`, `dateModified` from `git log -1 --format=%cI content/<slug>.md`, `author: { "@type": "Person", "name": "Collin (opencolin)" }`).
- [ ] Real `/404.html` page with site chrome, search box, and link back to home.
- [ ] Hash routes still work (`/#patterns` redirects to `/patterns/`).

### Measurement
- [ ] Plausible Cloud analytics snippet added (or environment-variable-gated equivalent).
- [ ] Custom event `outbound:click` fires on external link clicks.

## Files to Touch

| File | Why |
|------|-----|
| `content/manifest.json` (new) | Single source of truth for sidebar + slug list |
| `build.sh` | Read manifest; emit per-slug HTML; emit sitemap + robots; inject OG/Twitter/JSON-LD per page |
| `scripts/check-links.sh` (new) | CI link-checker |
| `.github/workflows/ci.yml` (new) | Run link check + `build.sh --check` |
| `api/og/[slug].ts` or `pages/api/og.ts` (new) | `@vercel/og` edge function |
| `vercel.json` | Add rewrite/redirect rules for hash → clean URLs (progressive enhancement only) |
| `index.html` (regenerated) | One per slug |
| `404.html` (new) | Fallback page |
| `robots.txt` (new) | Crawler rules |
| `sitemap.xml` (generated) | Built artifact |

## Out of Scope

- Astro migration (v1.4) — this release still uses `build.sh`.
- Newsletter (v2.0).
- GitHub Discussions / Suggest-an-edit (v2.0).
- New content pages (v1.3).

## Verification

1. Local: add a fake page to `manifest.json`, run `bash build.sh`, verify it appears in sidebar without any other edit.
2. CI: open a PR with a broken `[link](nonexistent.md)` — must fail link-check.
3. CI: forget to run `build.sh` after editing `content/*.md` — must fail `build.sh --check`.
4. Vercel preview: `view-source:` on each page shows page-specific `<title>` + OG tags.
5. Curl the OG endpoint for 5 different slugs; each returns a unique PNG.
6. `curl /sitemap.xml` returns valid XML with all slugs.
7. Google Search Console: submit sitemap.

## Hand-off Notes

The biggest risk is breaking the existing hash-route deep links shared on social. Tackle redirects first (in `vercel.json`), then per-page HTML. Use the Vercel preview to verify both `/#patterns` and `/patterns/` resolve to the same content.
